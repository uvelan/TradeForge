# Prioritized gap analysis

**Criteria** P0 affects trust, causality or recoverable data integrity. P1 materially affects reliability or analytics. P2 adds capability or performance. P3 is optional. Labels below distinguish reproduced findings, code inspection and policies that need an owner decision.

| ID | Priority / status | Exact evidence and consequence |
|---|---|---|
| G0 | P0 / code-inspected | `frontend/src/App.tsx::Terminal` strips the unconfirmed last bar only when replayIndex is null. Replay stepping can reach the raw array tail, send a forming bar to indicators and advance cutoff to its nominal future close. Pin a closed replay snapshot and drive both panes and indicator requests from its true availability frontier. |
| G1 | P0 / reproduced | `research_backend/app/main.py::backtest` checks provider, feed, symbol and basis. `tick_replay.py::replay_breakout` never compares overlapping bid OHLC to the quote stream. A saved-style M1 bar high of 101 accepted bid 106 and returned a 2.5 R target. A feed label or file checksum cannot certify mathematical consistency. |
| G2 | P0 / reproduced | `research_backend/app/indicator_routes.py::active_alerts` excludes only `smt_source_corrections`. An immutable confirmed alert with a later `SMT_INVALIDATED` row stayed active. `frontend/src/smt.ts::useSmt` clears the held badge for correction IDs only. Keep historical confirmations and project lifecycle state for current use. |
| G3 | P0 / reproduced | `research_backend/app/storage.py::write_partition` acknowledges a duplicate if its file exists. A temp-archive corruption probe returned the same ID as a successful duplicate, then `read_partition` rejected its checksum. The fixed-point `Catalog.publish` conflict path also omits integrity verification (inspection). A file rename before commit can leave an orphan if the process dies. |
| G4 | P1 / reproduced policy ambiguity | `tick_replay.py::replay_breakout` uses the triggering quote and adverse bps for every exit. A 105 target filled at 130 for 14.5 R. A stop-crossing quote at expiry is labeled TIME_LIMIT. This is coherent for some trigger-market policies, but no recorded order type, latency, same-time policy, depth or target cap establishes realistic fill behavior. |
| G5 | P1 / partial, inspected | `main.py::backtest` loads one <=500,000-quote partition and <=700 candles via `storage.read_partition`; `saved_history.saved_range` handles candles only and recent truncation. `tick_replay.replay_breakout` uses a universal max gap (60s default, capped by bar width) plus adjacent candles. Thin legitimate sessions can be unresolved while a shorter outage passes. Time-ordered batches, instrument/calendar intervals and explicit untrusted status are missing. |
| G6 | P1 / partial, inspected | `indicator_routes.py::poll_monitor` reads latest 600 and `capture_live_smt` floors alerts at now minus two bars. Reconnect can classify recent evidence but silently skip alerting older missed events and has no gap watermark. `smt_history.record_smt` uses transactional uniqueness and checks the configuration token, but no cross-process poll owner or monotonic capture watermark. Restart/two-process races and real MT5 were not validated. |
| G7 | P1 / partial, inspected | `smt_history.py::scope_key,record_source_corrections,record_smt` use scope plus pivot snapshot keys and then suppress by corrected logical ID within that scope. Revised saved partition IDs create a new scope; revised live evidence in the same scope can remain suppressed even when independently valid. Corrections compare an overlapping 600-bar window only. Separate semantic event ID, evidence revision and alert lineage. Exact UTC matching, seven-bar timing and changed capture correction are already tested. |
| G8 | P1 / partial, inspected | `tradeforge/catalog.py::Catalog` and research `storage.py::write_partition` encode different timestamps/scales, IDs and range semantics. `research_backend/app/main.py::import_dukascopy_bi5` publishes raw ticks and derivation in separate operations. Partial import can be catalog-visible. There is no quota, provider manifest, offline reconciliation or restore acceptance gate across both stores. |
| G9 | P1 / missing authority | `research_backend/app/risk.py::evaluate` uses user pip value and illustrative 0.01 lots. `main.py::import_deals` uses insert-or-ignore by account/deal key, while `domain.py::analytics` aggregates user-entered outcomes. Broker correction, dated specs, leverage, currency conversion, account balance transfers, netting/hedging, fees/swap and position episodes require new ledger logic. UI/API should preserve the existing illustration label. |
| G10 | P1 / partial, inspected | `domain.py::_package_files,export_ai,import_ai` verify package hash and typed Decimal references, but model-normalized JSON is stored instead of original bytes and duplicate lookup precedes insertion. Packages are PLAN/RISK/TIMELINE only, with no verified market run or metric lineage. `get_trade` assembles multiple reads, while export stamps cutoff afterward. Require one read snapshot, content-addressed raw bytes, and separate analyst accept/reject records. |
| G11 | P2 / partial | `indicators.py::average,atr,rsi,macd,swing_points,calculate` have prefix tests but registry warm-up counts are first-output minima. Swing confirmation output uses opening time plus an implied close convention; general indicator route validates ordering, not closed/gap-aware availability. ATR seeds first high-low, flat RSI is 50, MACD separate seeds and early preview. These are conventions to document and compare, not presumed numerical errors. ADX, Stochastic, structure, FVG/OB, CRT and HTF are unimplemented families. |
| G12 | P2 / unbenchmarked | `frontend/src/components.tsx::CandleChart` sorts/resets candle data and rebuilds line series for SMT segments. `chartViews.tsx` separate charts, native panes and replay use different lifecycles. Measure 1-4 charts with many annotations first. `App.tsx::StrategyLab` exposes gap setting but lacks a complete execution manifest and visual gap timeline. |

Risk posture for unresolved trades: a detected integrity mismatch is `UNTRUSTED`; a valid archive that cannot establish a fill is `UNRESOLVED`; known closures classify coverage but do not create prices, prove fill size or automatically make an overnight carry valid.
