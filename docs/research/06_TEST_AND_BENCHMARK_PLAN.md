### Executed exact SMT clock probe

Map the default timing fixture in `test_smt.py::test_default_timing_keeps_confirmation_out_of_earlier_prefixes` onto M5. Start 9×300 seconds before 01:50 IST on 14 Nov 2026; delay the second series by 0, 1 or 2 bars (pad with price 29 before its first value). With 3 right bars, UTC match 2 and one shared confirmation bar, no event with 14 closed bars, candidate at 15, confirmed at 16, stable at 17. At 0-bar offset, all pivots are known at 02:10 IST, the corresponding match window closes at 02:20, and the next shared bar closes at 02:25. At 1/2 offset the latest pivot becomes known at 02:15/02:20, the match frontier still closes at 02:20, and confirmation remains 02:25. 01:50 IST = 20:20 UTC previous day; 02:25 IST = 20:55 UTC. This validates rule timing with synthetic data. The historical broker screenshot requires its sealed broker candle capture, rules, and matching feed/timezone.

### Numerical, provenance and UI suites

- Full history vs every prefix with visibility based on `available_at`; construct adversarial suffix changes and exact expectations for entries/exits and anchor/confirmation events. Add reproducible seeded property tests for out-of-order quotes, bid/ask inversion, timeframe alignment and empty intervals.
- Same tail with 1×/3×/10× minimum startup history for EMA, RSI, ATR, NATR and MACD, using stable independent oracle fixtures. Compare first eligible output separately from convergence. Include monotone, flat, NaN/gap and large-scale offset inputs. Proposed compatible numeric tolerance is max(1e-10 absolute, 1e-8 relative) on float-compatible cases and exact prices in instrument units. Document justified convention differences rather than forcing tolerance.
- CRT fixture has a frozen completed reference candle, wick sweep, reclaim close, invalidation and accepted subsequent opportunity. Check no availability during the sweep or incomplete HTF/LTF bar. Session/kill-zone tests cover regional DST changes, calendar holidays and UTC half-open edges.
- Windows broker acceptance uses a read-only account, redacted evidence, restart/disconnect of MT5 and API, live closed bars, file lock/low disk, backup/restore, pinned Python/Node and matching CSS/chart snapshots. Verify one/two/four charts, cursor crosshair UTC mapping, pane vs overlay, full view, user color/timezone persistence, invalidation removal, and replay source badges.

## Proposed performance workloads

Record SHA256 for every input file, unified manifest SHA, expected reference hashes, software pins, CPU/logical cores, RAM, disk/model and size, OS, thread caps, engine config, seed and timer. Use three warmups and at least seven measured runs with fixed seeds; report p50/p95, process CPU including children, RSS/peak working set, ingest+query wall time, rows/sec, disk bytes before/after, IO and event/metric hash. Separate cold (fresh process and disclosed OS cache state) from warm. Measure target hardware in a quiet local window. Large vendor datasets were not available for this audit.

| Dataset / workload | Test design and proposed gate |
|---|---|
| One EURUSD tick day | Cold/warm verified time-range scans, decode→Parquet→query→replay separately. Compare sorted quote count, disk and hashes. No full-day read for an hour query if row-group predicates apply. |
| One EURUSD month | Include weekday, weekend, sparse/gapped suspension and DST when present. Measure random date windows, archive rollup and streaming replay. Proposed peak <512 MiB for production-path replay on local machine; include export overhead. |
| One year one instrument | 12 monthly slices; scan/replay with cross-partition positions and conflict check. Peak memory must be independent of total rows within batch envelope; verify no truncated run masquerades complete. |
| Multi-instrument, multi-timeframe | FX three pairs and metal; derive M1/M5/M15/H1, filter by symbol/feed/time. Compare catalog size, read latency and queries with optional DuckDB, identical manifest. |
| Millions of events | Synthetic 1m/10m including same-ms ties, spread/liquidity changes, gaps and known outcomes. Require three identical result hashes and fixed seeds where used. Compare optional engines only after passing fill goldens, including conversion overhead. |
| Repeated SMT | 600 bars × two, 24h simulated polls, unchanged capture and new bar/revision cases. Measure allocation/SQLite lock time, p95 API, exact journal/notification counts. CPU target follows a baseline; no duplicate event/alert required. |
| Strategy search and indicators | 100 configurations over frozen train/validation/test folds plus 1M indicator inputs in batches. Bound memory, freeze out-of-sample IDs, require equivalent outputs and report incomplete cases. |
| Charts | 1/2/4 chart views, 600/5,000/50,000 bars and 25/250/1,000 annotations with replay and panning. DevTools trace p95 frame time and JS heap, record zoom/DPI. Proposed p95 <33 ms for the agreed supported workload and no memory creep after 30 mounting cycles. Do not set 50k/1k as a product promise without profiling. |
