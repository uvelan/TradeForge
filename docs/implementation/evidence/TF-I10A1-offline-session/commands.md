# Reproduction commands

Use the project virtual environment from the repository root. The first approved bounded run used the reviewed merge before any code changes.

```powershell
git fetch origin
git fetch origin main
git rev-parse origin/main
python -m pytest -q -s 'research_backend/tests/test_bounded_crt_smt_successors.py::test_scheduler_equivalence_and_completion_gate[7200]'
$env:TRADEFORGE_BENCH_OUTPUT = (Resolve-Path 'docs/implementation/evidence/TF-I10A1-offline-session').Path
$env:TRADEFORGE_BENCH_PATH = 'fresh'
python -m pytest -q -s --tb=short research_backend/tests/benchmark_offline_crt_smt.py::test_measure_session
$env:TRADEFORGE_BENCH_PATH = 'optimized'
python -m pytest -q -s --tb=short research_backend/tests/benchmark_offline_crt_smt.py::test_measure_session
python -m pytest -q -s --tb=short research_backend/tests/benchmark_offline_crt_smt.py::test_session_recovery_and_equivalence
python -m pytest -q --tb=short research_backend/tests/test_bounded_crt_smt_successors.py research_backend/tests/test_historical_successor_oracle.py research_backend/tests/test_historical_strategy_runs.py research_backend/tests/test_historical_publication_v2.py research_backend/tests/test_strategy_evaluator.py research_backend/tests/test_negated_current.py
python -m pytest -q --tb=short research_backend/tests/test_bounded_crt_smt_successors.py::test_offline_archive_cache_keeps_exact_prefix_and_public_limit
python -m compileall -q research_backend
$env:PYTHONPATH = (Get-Location).Path
python scripts/verify_real_strategy_evaluation.py --historical
git diff --check
```

The bounded profile used a temporary wrapper around the first scheduler invocation in that exact pytest node. It ran the original function via `cProfile.Profile().runcall` and collected its checkpoint callback's decision and opportunity batches through completion. The committed bounded profile retains the timing lines and final pytest result. The companion JSON contains the entire initial ledger.

The separate fresh and optimized pytest processes each create the same deterministic archive, strategy IDs and run identity. Each first invocation is process-cold with no preceding evidence collection. The second invocation is warm in that process. OS page caches were not flushed, and each optimized invocation starts its own verified replay cache. Timings include verified horizon collection and per-cutoff hashing for both paths. The recovery invocation uses the unabridged fresh and optimized JSON generated by the measurement commands.

The committed comparison JSON keeps the common complete ledger and per-cutoff traces, plus both paths' observed measurement sets. The two generated intermediate JSON files are only needed to run the recovery comparison.
