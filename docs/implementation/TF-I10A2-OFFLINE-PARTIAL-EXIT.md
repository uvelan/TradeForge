# Offline partial exit

The versioned `OFFLINE_PARTIAL_EXIT` policy supports one partial reduction with a fixed initial stop and a reward-multiple target. It does not combine with break-even, trailing or time-based management. The existing immutable fixed and break-even result contracts and identities are unchanged. Earlier unsupported results remain archived under their original policy identities.

The threshold is the verified entry fill plus the signed initial risk multiplied by the frozen partial R value. The level must be on the tape's exact price grid, strictly between the entry and final target. The partial closes the configured percentage of the **original normalized position**, not actual broker lots. The result stores closed and residual fractions as reduced integer numerator/denominator pairs, without rounding. No liquidity, size, fees or accounting model is implied.

Use executable bid for a long exit and executable ask for a short exit. At each quote priority check the existing fixed stop and final target first. If a quote gaps directly to the final target, the closing quote proves a terminal exit only, not an invented intermediate partial fill. Otherwise the first valid partial touch closes the requested fraction at that quote. A later stop or target closes only the remaining fraction. A tied priority with distinct rows cannot establish a partial or a terminal exit. Continuous delivery coverage is required through each accepted event; a later hole does not erase an earlier verified reduction.

`partial_exit` and `exit` are separate, with stable event IDs across extensions of the same pinned tape's cutoff. In a covered partial-only horizon the result remains `OPEN_AT_CUTOFF`; the singular `exit` stays null. `simulated_partial_exits` is reported only for partial-policy evaluations with a verified entry. `simulated_exits` still counts terminal liquidations, not reductions. The service reads, verifies and preserves original entry and strategy evidence. Public admission, account publication and recorded trading remain unchanged.

Run `python -m pytest -q research_backend/tests/test_offline_partial_exit.py research_backend/tests/test_offline_first_exit.py`. The service tests cover both directions, exact fractional quantity, stop and target residuals, direct target gaps, same-priority touch/miss in both input orders, cutoff extension/rewind, and a quote coverage hole after a verified reduction. Reverting the implementation restores unsupported handling without rewriting persisted evidence or requiring a SQLite migration.
